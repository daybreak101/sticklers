- 2 apps: customer app, admin dashboard app

Customer App:
- Create account
- Menu browsing
- Searching
- Cart + checkout
- order status (received, preparing, ready)

Frontend:
- React Native (with Expo)
- State: Zustand / Redux Toolkit
- Networking: Firebase SDK

Pattern:
1. Fetch menu on app start
    const menu = await getMenuFromFirestore()
2. Store locally (Zutand/Redux or AsyncStorage)

Backend:
- Authentication: Firebase Auth
- Database: Firestore

Admin Dashboard App:
- New orders, button to click finish
- Today's orders
- History of orders
- Get live orders
    query(
        collection(db, "orders"),
        where("status", "in", ["pending", "accepted", "preparing"]),
        orderBy("createdAt", "desc")
    )

Strategies to limit read requests
1. Don't use onSnapshot on menu, do it where it matters, such as realtime orders
2. Cache aggressively (Zustand/Redux or AsyncStorage)
3. Versioning
    menuMeta/version 
    - app fetches version, compare with local version; if different, fetch from server
4. Reduce document count
   Bad: menuItems (100 docs)
   Good: menu (1 doc with array)
5. Query only what you need
   Bad: getDocs(collection(db, "orders"))
   Good: query(
        collection(db, "orders"),
        where("status", "==", ["pending"]),
        orderBy("createdAt", "desc"),
        limit(10)
    )
6. Avoid duplicate fetches
   Common mistake: 
      useEffect(() => {
        fetchMenu()
      }, [])
7. Guard against abuse
      Firestore security rules:
            allow read: if request.auth != null;
